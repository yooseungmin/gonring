# 인라인 AI(PRD) — HAW Assistant (HWP)

## 배경
한컴독스 AI를 포함한 인라인 AI 서비스는 선택 텍스트를 즉시 재작성하고, 톤/길이/번역 등 빠른 변형을 제공하며, 여러 제안을 비교·적용하는 흐름이 표준이 되고 있다. HAW Assistant는 HWP 환경의 선택 텍스트 재작성 워크플로우를 가지고 있으나 품질·변형·UX·신뢰성 면에서 기준에 미달한다.

## 목표
1. 선택 텍스트 기반 인라인 리라이트 품질을 상용 수준으로 끌어올린다.
2. 한컴독스 AI의 핵심 기능(문체 변경, 요약, 번역, 맞춤법/문법 개선 등)과 동급 경험을 제공한다.
3. 다중 제안, 재생성, 인라인 편집, 안전한 적용 흐름을 구현한다.
4. HWP COM 의존 환경에서도 안정성과 복구성을 확보한다.

## 비목표
1. 문서 전반의 완전 자동 작성(초안 자동 생성)은 1차 범위에서 제외한다.
2. 다중 OS 지원 확장(macOS/Linux HWP 실행)은 범위 밖이다.
3. 설치/업데이트 파이프라인과 상용 결제 연동은 2차 범위로 둔다.

## 사용자/시나리오
1. 사내 문서 작성자: 문장 다듬기, 공식 문체 적용, 중복 제거.
2. 기획/정책 담당자: 문장 길이 조정, 요약, 용어 통일.
3. 번역/대외 문서 작성자: 선택 문단 즉시 번역, 톤 변경.

## 핵심 사용자 여정
1. HWP에서 텍스트 선택.
2. 도킹 UI에서 프리셋 선택 또는 커스텀 프롬프트 입력.
3. 3~5개의 제안 결과 확인.
4. 제안 내부를 직접 편집(선택사항).
5. 교체/삽입 중 선택하여 적용.
6. 적용 이력에서 되돌리기 또는 재생성.

## 기능 요구사항
### 1. 리라이트 엔진
1. 최소 3개의 결과 버전 제공.
2. 재생성(동일 프롬프트로 다시 생성) 지원.
3. 프리셋 변형 지원.
4. 커스텀 프롬프트 지원.
5. LLM 실패 시 폴백 품질 보장.

### 2. 프리셋 변형(한컴독스 AI 기준)
1. 문체 변경(격식/친근/간결/공식).
2. 길이 축소/확장.
3. 맞춤법/문법 개선.
4. 요약.
5. 번역(KO↔EN 우선).
6. 이어쓰기(선택 영역 다음 문장 제안).

### 3. UI/UX
1. 도킹 UI에서 다중 제안 카드 제공.
2. 제안 카드 내 직접 편집.
3. 적용 방식 선택(교체/아래 삽입).
4. 프리셋 버튼 + 커스텀 입력 동시 제공.
5. 마지막 제안 히스토리 최소 5건 유지.
6. 키보드 단축키 유지 및 확대.

### 4. 정책/가드레일
1. 기존 `policy.toml` 기반 차단/경고 유지.
2. 표/민감 영역에 대한 안전 모드 기본 활성.
3. 사용자에게 차단 사유 명확히 노출.

### 5. 안정성/복구
1. COM 오류 재시도 및 실패 복구 안내.
2. 클립보드 의존 최소화(가능한 HWP 액션 API 우선).
3. 선택 영역 변경 감지 및 안전 적용.
4. 크래시/오류 로그 수집(로컬).

## 비기능 요구사항
1. 평균 응답 5초 이내(90p).
2. 최대 입력 6,000자 기준 동작.
3. 단일 요청 실패율 1% 이하 목표.
4. 로그에 민감정보 마스킹.

## 기술 요구사항(아키텍처 정렬)
1. `haw.services.llm_client`를 프로바이더 레이어로 확장.
2. 다중 결과 반환 스키마 도입.
3. `haw.agent.proposal_store`에 히스토리 저장 구조 추가.
4. `haw.ui.dock_panel`에 제안 리스트/편집 UI 추가.
5. 정책 위반 시 제안 생성 차단과 명확한 메시지 반환.

## 데이터/보안
1. API 키는 `.env`에서 로딩.
2. 요청/응답 로그는 옵션으로 저장, 기본 비활성.
3. PII 마스킹 규칙을 정책 레이어에서 적용.

## 지표
1. 제안 채택률(accept).
2. 재생성 비율.
3. 편집 후 적용 비율.
4. 실패율 및 평균 응답 시간.
5. 클립보드 복구 실패율.

## 범위별 단계
### Phase 1: 상용 수준 리라이트
1. LLM 프로바이더 안정화.
2. 다중 제안 + 재생성.
3. 프리셋 4종(문체, 길이, 맞춤법, 요약).

### Phase 2: HWP 안정성 강화
1. 클립보드 의존 최소화.
2. 선택 영역 손실/변경 복구.
3. 제안 히스토리/되돌리기.

### Phase 3: 확장
1. 번역/이어쓰기 고도화.
2. 운영 지표 대시보드(로컬).
3. 배포/업데이트 파이프라인 정비.

## 수용 기준(DoD)
1. 선택 텍스트 기준 3개 제안이 생성된다.
2. 각 제안은 편집 후 적용할 수 있다.
3. 프리셋 4종이 동작한다.
4. 오류 발생 시 사용자에게 복구 가이드가 노출된다.
5. 단위 테스트 및 핵심 스모크 테스트 통과.

## 리스크
1. HWP COM 환경 편차로 인한 불안정성.
2. LLM 응답 형식 불일치로 인한 파싱 실패.
3. 클립보드 충돌로 데이터 유실 위험.

## 오픈 이슈
1. 한컴독스 AI 기능 범위의 정확한 최신 스펙 반영 필요.
2. 상용 모델 선택(Claude/OpenAI/다중) 전략 결정 필요.
3. 프롬프트 템플릿/품질 평가 방식 정의 필요.
